# Kakao Theme Studio로 테마 제작하기

Codex와 Claude Code에서 같은 절차를 사용한다. 로컬 파일·명령 실행·브라우저 기능은 현재 도구가 제공하는 것을 사용한다. 특정 MCP, 플러그인, 다른 스킬이 설치되어 있다고 가정하지 않는다.

## 작업 범위

**별도 요청이 없으면 스튜디오 도구 자체를 수정하지 않는다.** 테마 제작·편집·생성 요청은 프로젝트 설정, 원본 에셋 등록과 생성 결과만을 대상으로 한다. `src/`, `public/`, `templates/`, 앱 실행 스크립트, 의존성, 테스트를 고쳐 테마 요구를 구현하지 않는다. 지원하지 않는 디자인이나 오류는 한계·재현 조건으로 보고하고 지원 범위 안의 방법으로 진행한다. 사용자 프로젝트·키·기존 결과를 자동 정리하지 않는다.

안전 조건에 맞는 Git 최신화는 원격의 기존 변경을 가져오는 준비 작업이다. 직접 코드 수정·커밋·push·충돌 해결까지 허용하는 것은 아니다. 스튜디오 개발을 명시적으로 요청받은 경우에만 저장소 개발 지침으로 전환한다.

## 시작

1. 사용자가 지정한 저장소를 우선한다. 없으면 현재 폴더의 상위에서 `package.json`, `src/catalog.mjs`, `src/server.mjs`가 있는 스튜디오 루트를 찾는다. 그래도 없으면 이 스킬의 실제 위치에서 저장소를 찾는다. 서로 다른 사본이나 `.data`를 임의로 합치지 않는다. 찾지 못했을 때만 경로를 묻는다. 최초 실행・새 호스트에서는 [설치와 실행 환경](references/environment.md)을 읽고 Node와 고정 의존성부터 확인한다. Node가 없으면 다음 준비 스크립트도 실행할 수 없다.
2. 해당 저장소의 `AGENTS.md`와 `CLAUDE.md`가 있으면 읽고 적용한다. 실행 중인 편집·생성이 있거나 사용자가 갱신을 원하지 않으면 최신화를 생략한다. 그 외에는 작업 시작 시 아래 준비 스크립트를 한 번 실행한다. `SKILL_DIR`은 지금 읽은 스킬 폴더의 절대 경로, `REPO`는 확인한 저장소 절대 경로로 치환한다.

   ```sh
   node "SKILL_DIR/scripts/prepare.mjs" --repo "REPO" --pull
   ```

   `--pull`을 빼면 읽기 전용 점검이다. 미커밋 변경·upstream 없음·분기·진행 중 Git 작업·인증/네트워크 실패는 자동 복구하지 않는다. 실패·생략을 알리고 가능한 범위의 작업을 계속한다. 최신 확인이 안 된 상태를 최신이라고 말하지 않는다.
3. 갱신 후 이 저장소의 `skills/kakao-theme-studio/SKILL.md`, 적용 지시 문서, `README.md`, `docs/HANDOFF.md`를 다시 읽는다. `AGENTS.md`가 요구하는 문서도 따른다. 설치한 스킬 사본보다 대상 저장소의 최신 절차를 기준으로 한다. 버전·지원 슬롯 수는 고정값 대신 준비 결과와 현재 카탈로그를 사용한다. 문서와 소스가 다르면 차이를 알린다.
4. [편집 절차](references/editing.md)를 읽는다. 생성·서명 또는 실행 환경 문제가 있으면 [생성과 실행](references/build.md)도 읽는다. API로 편집할 때는 현재 `docs/ARCHITECTURE.md`와 `src/server.mjs`의 실제 계약을 확인한다. 추측한 API나 지원하지 않는 CLI 명령을 만들지 않는다.
5. 준비 스크립트를 `--pull` 없이 `--doctor`로 실행해 기존 `doctor()` 결과를 확인한다. [설치와 실행 환경](references/environment.md)에 따라 실행용 Node/의존성, Android용 JDK 17 이상·안정 SDK Platform/Build Tools 37 이상, 선택적인 브라우저 테스트/기기 도구를 구분한다. 갱신된 저장소 정책이 우선이다. `doctor.status=checked`나 exit 0만 보지 말고 `environment.ok`, `missing`, 실제 `javac` 버전과 JDK/SDK 경로를 확인한다. 부족한 환경은 기존 권한과 요청 범위에서 준비하며 앱 소스·의존성 버전·lockfile을 임의 수정하지 않는다. 설치 안내만 요청받았으면 실제 호스트에 설치하지 않는다.
6. 저장소·앱/컴파일러 버전·최신화 결과·대상 프로젝트/플랫폼·데이터 위치·환경 부족분을 간단히 전달하고 작업한다. 이미 알려진 항목은 다시 묻지 않는다. 기존 프로젝트가 여러 개여서 대상이 불명확하면 쓰기 전에 대상을 확인한다.

## 편집과 완료

- 기존 UI 또는 인증된 로컬 서버 API로 프로젝트를 편집한다. API 요청 전 활성 브라우저의 미저장 편집·복구 충돌을 확인하고 오래된 프로젝트 사본으로 덮어쓰지 않는다. 원본 파일 직접 덮어쓰기나 사용자 저장소에 low-level import를 사용하지 않는다.
- 공통값·플랫폼 예외·최종 출력 예외를 구분한다. 예외 해제, 디자인 복제, 배경 적용/원본 보관은 사용자 의도에 맞춰 수행한다. 색이 안 바뀐다고 예외나 팔레트를 일괄 초기화하지 않는다.
- 미리보기는 현재 설정에서 실제 생성된 그림으로 확인한다. 양방향 첫/연속, 짧은/긴 문장, 관련 상태와 대상 플랫폼을 검사한다. 탐색·문장 프리셋·플랫폼 보기는 출력 설정과 구분한다.
- 저장 완료와 현재 revision을 확인하고 요청한 결과를 생성한다. 생성 작업의 실제 상태를 조회하며 임의 진행률·성공 추정을 표시하지 않는다. 브라우저 연결 실패만으로 새 빌드를 반복 요청하지 않는다.
- 결과 파일 경로, 플랫폼별 성공/부분 성공/실패, 현재 설정·컴파일러와의 일치, 남은 확인을 전달한다. 소스 ZIP을 APK로 보고하지 않는다. 실제 카카오톡 적용은 별도 기기 근거가 있을 때만 확인 완료로 기록한다.
- 토큰·키 비밀번호·개인키를 응답/로그/스크린샷/프로젝트 ZIP에 포함하지 않는다. 키가 없으면 기존 키 복원을 안내하며 임의의 새 키로 대체하지 않는다.

## 실행 권한이 없는 환경

Claude 웹 채팅처럼 로컬 저장소·서버에 접근할 수 없으면 디자인 계획, 에셋 역할과 사용자가 실행할 절차까지 제공한다. Git pull·저장·컴파일·기기 적용을 수행했다고 주장하지 않는다. 클라우드 컨테이너에 이 스킬만 올려도 사용자 Mac의 저장소·서버·서명키에 접근할 수 있는 것은 아니다. 도구별 배치와 이식 범위는 [공통 스펙](references/spec.md)을 따른다.
