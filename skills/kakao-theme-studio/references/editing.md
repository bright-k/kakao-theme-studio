# 테마 편집 절차

## 현재 작업 정하기

새 제작인지 기존 수정인지, 대상 프로젝트·플랫폼·원하는 결과를 사용자 요청에서 정한다. 기존 프로젝트는 이름과 packageId를 함께 확인한다. 요청 범위 밖의 프로젝트, 원본, 서명키와 과거 결과는 보존한다. 테마 작업만 요청받았으면 스튜디오 코드에 패치를 적용하지 않는다.

기존 UI를 사용할 수 있으면 저장/임시 복구/실행취소가 연결된 UI를 사용한다. UI 자동화 기능이 없고 로컬 명령만 가능하면 실제 서버 API를 사용한다. 활성 창의 미저장 상태가 API 조회의 저장본에 반영된다고 가정하지 않는다. 충돌 해결 전 외부 PUT으로 덮어쓰지 않는다. 자동화 기능 자체를 추가하는 제품 코드 수정도 별도 요청 대상이다.

## 색상과 원본

- 같은 역할의 양 플랫폼 변경은 공통색·공통 원본부터 사용한다. 특정 화면·플랫폼만 요청한 경우 해당 override를 사용하고 공통 팔레트를 임의 변경하지 않는다.
- 이미지 비활성화가 최우선이다. 최종 `resourceOverrides`는 플랫폼 본체/캐릭터와 공통 합성보다 우선한다. 플랫폼 입력이 없으면 공통 정책을 상속한다. 가이드만 있는 예외와 이미지 교체는 구분한다. 현재 실제 출처는 미리보기의 provenance 및 카탈로그로 확인한다.
- 공통 변경이 보이지 않으면 적용 모드와 가려진 예외를 먼저 확인한다. 전체 예외 삭제 대신 요청 대상만 명시적으로 공통 연결한다. 비활성·대체 원본도 보존한다.
- 배경의 `이미지 등록하고 적용`은 모드를 켜며 `원본만 등록`은 현재 모드를 유지한다. 색상만 사용은 이미지를 끄되 원본·크롭·출력 예외를 보존한다. 플랫폼 색상 예외도 자동 해제하지 않는다.
- 모든 색은 HEX 입력을 사용한다. Android `#AARRGGBB`의 AA는 RGB 변경 때 보존한다.
- 변경 이미지는 업로드해 새 불변 버전으로 등록한다. `assets/index.json`, 해시와 참조를 앱이 관리하게 한다. 폴더의 가장 큰 버전 번호를 현재 원본으로 추정하지 않는다.

## 말풍선과 가이드

- 보낸/받은, 첫/연속의 본체와 캐릭터를 구분한다. 플랫폼 본체 교체는 공통 캐릭터를 끊지 않으며 본체와 캐릭터 복귀도 독립적이다. 첫/연속의 글자색은 실제 플랫폼 속성이 공유할 수 있다.
- 공통 본체는 가이드 없는 PNG다. 등록하면 해당 본체의 이미지 모드가 활성화된다. Android 원본 `.9.png`의 1픽셀 가이드를 유지하려면 플랫폼별 최종 출력 교체를 사용한다. 이 경우 공통 캐릭터 합성보다 우선한다.
- iOS는 논리 1배수 가이드, Android는 파일별 물리 픽셀의 늘림/내용 가이드를 사용한다. 논리·물리 좌표와 본체 `bodyRect`·그림 전체의 투명 여백을 섞지 않는다.
- 캐릭터 위치·크기 조절 뒤 한 글자/긴 문장의 본체 크기·본문 여백·그림 잘림을 함께 확인한다. 캐릭터를 켰다고 본문 여백을 임의 증가시키지 않는다. 기존 안전 범위 컨트롤과 시각 편집기를 사용한다.

## 저장과 확인

상단 저장 상태를 확인하고 필요하면 저장 버튼으로 반영한다. 정식 저장이 실패한 임시본을 생성 완료로 취급하지 않는다. 미리보기가 현재 설정의 생성 그림으로 갱신되었는지 확인한다. 받은 첫·연속/보낸 첫·연속 네 상태, 짧은/긴 문장과 필요한 선택·누름 상태를 대상 플랫폼에서 검토한다. 비교·화면·플랫폼·문장 전환만으로 프로젝트를 바꾸지 않는다.

일반 테마 제작에는 앱 소스 회귀 테스트 전체를 실행할 필요가 없다. 요청한 저장·원본 등록·미리보기·실제 결과를 확인한다. 스튜디오 개발을 별도 요청받았다면 저장소 AGENTS/TESTING에 따라 `.test-data`에 격리해 테스트하고 HANDOFF/VERIFICATION을 갱신한다.
