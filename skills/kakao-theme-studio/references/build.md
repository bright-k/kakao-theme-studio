# 실행·서명·생성

## 준비

최초 설치·새 호스트·환경 오류는 먼저 [설치와 실행 환경](environment.md)을 읽는다. Node·고정 pnpm 설치, JDK/SDK 준비, 환경변수와 라이선스, 선택 도구 및 완료 판정은 해당 문서가 공통 기준이다. 확인한 저장소를 cwd로 사용하고 lockfile을 다시 만들거나 의존성을 업그레이드하지 않는다.

```sh
node src/cli.mjs doctor
node scripts/launch.mjs
```

doctor는 SDK/JDK 탐색의 기준이다. 플랫폼·Build Tools 부족 시 출력한 설치 안내를 현재 공식 SDK 도구와 대조하고 구형 SDK로 우회하지 않는다. 준비 스크립트의 `--doctor`는 같은 CLI를 실행하고 결과를 JSON으로 요약한다. `status=checked`와 실제 `environment.ok`를 구분하고 Java 버전도 직접 확인한다. iOS 생성만 필요한 경우 Android 환경 전체를 필수로 설치하지 않는다.

데이터 루트는 실제 실행 환경의 `THEME_STUDIO_DATA` 또는 저장소 `.data`다. 서버가 다른 환경변수로 실행됐다면 현재 셸의 추정값과 다를 수 있으므로 UI의 저장 위치를 대조한다. 테스트용 데이터 루트를 실제 제작 서버에 연결하지 않는다.

런처는 기존 인증 세션을 사용하고 호환 서버를 재사용한다. 소스와 실행 서버의 컴파일러 버전이 다르면 저장·임시본·생성 상태를 확인한 뒤 정상 종료/재시작한다. 준비 스크립트는 서버를 종료하거나 재시작하지 않는다. 인증 링크의 fragment와 `.data/session.json`을 그대로 출력하지 않는다. 브라우저를 열 때만 인증 링크를 사용한다.

## 서명

기존 프로젝트의 package ID·서명 fingerprint·versionCode 연결을 유지한다. 키 선택/잠금 해제는 앱의 서명키 관리에서 사용자가 입력하도록 한다. 비밀번호를 채팅에 요구하거나 명령 인자/로그/스크립트에 쓰지 않는다. 키가 사라졌으면 백업 복원으로 연결한다. 신규 프로젝트의 키 생성도 사용자 의도에 따라 수행한다.

프로젝트 ZIP은 디자인/참조 이미지 백업이며 키 복원이 아니다. 키 백업은 별도의 암호화 파일이다. `.data`, `.test-data`, 세션, 개인키를 스킬 배포나 소스 ZIP에 넣지 않는다.

## 생성

저장 오류·복구 충돌을 해결하고 현재 프로젝트에서 `두 플랫폼 생성`을 실행한다. API를 사용할 때는 현재 `/api/build`, `/api/job`, `/api/builds`, `/api/download` 계약을 소스에서 확인한다. CLI의 `build`는 두 플랫폼 생성이며 임의의 iOS 전용 플래그를 만들지 않는다. 서버와 CLI가 같은 데이터 루트를 동시에 열어 빌드하지 않는다.

서버의 실제 단계와 작업 ID를 추적한다. 연결 실패 시 같은 작업을 다시 조회하고 중복 빌드부터 만들지 않는다. 서버 재시작 뒤 작업 ID가 조회되지 않으면 최근 생성 결과와 보고서를 확인하되 완료를 추정하지 않는다. 키 잠금/환경 문제로 iOS만 완성될 수 있으므로 플랫폼별 결과를 확인한다.

완료 시 요청한 `.ktheme`, 서명된 `.apk`, 결과 ZIP/보고서 중 실제 존재하는 파일을 제공한다. 현재 compilerVersion 및 정확한 프로젝트 revision과 일치하는지 확인한다. 이전 다운로드 파일은 앱 최신화만으로 갱신되지 않는다. Android 소스 ZIP을 완성 APK로 보고하지 않는다.

## 검증 수준

미리보기 확인, 패키징·서명 확인, APK 설치, 실제 카카오톡 인식·적용은 다른 검증이다. 실제 적용을 확인하지 않았다면 `deviceVerified`/`actualAppVerified`를 true로 바꾸지 않는다. 실기기 적용 확인 시 기기·OS·카카오톡 버전과 관찰 근거를 남기며 개인정보를 캡처에 포함하지 않는다. 사용자 실제 기기/계정 접근은 대상과 권한을 먼저 확인한다.

스튜디오 출력을 고치는 개발 요청이라면 AGENTS의 컴파일러 버전 갱신·실제 통합 APK/ktheme·서명 후 무변경·resources.arsc STORE/4바이트 정렬 계약을 지킨다. 테마 디자인만 바꿀 때 앱/컴파일러 버전을 올리지 않는다.
