# 0.6.0 패키지명별 프로젝트 저장소

구현일: 2026-10-26. 앱/컴파일러 0.6.0, 로컬 저장 배치 버전 2, 프로젝트 백업 포맷 2다. 테마 schemaVersion 1과 카카오톡 출력의 이미지·속성 계약은 유지한다.

## 현재 디렉터리

```text
.data/
  projects/<packageId>/
    storage.json
    theme.json
    assets/<sha256>.png
    previews/<revision>/
    builds/<build-id>/
    backups/<테마-패키지명-시각-ID>.zip
  keys/                       # 기존 제작자 키
  bindings/<project-id>.json   # 기존 패키지/인증서/versionCode 연결
  .staging/                   # 등록 전 준비 영역
  .storage.lock               # 실행 중 저장소 잠금
  session.json
```

패키지명의 점은 그대로 쓰며 하나의 폴더다. 테마 이름은 바꿀 수 있지만 폴더명·packageId·project ID는 유지한다. 내부 식별과 API는 기존 project UUID를 계속 사용한다. 자동 발급한 긴 패키지명도 임의로 바꾸지 않는다.

프로젝트별 원본은 독립 파일이다. 같은 내용의 이미지는 한 프로젝트 안에서만 재사용하며 복제/새 프로젝트로 복원할 때 참조 파일을 실제 복사한다. 하드링크나 다른 프로젝트/구형 공용 assets로의 자동 fallback은 사용하지 않는다. 이름 변경, 모드 전환, 실행취소/다시실행에 필요한 파일은 자동 삭제하지 않는다.

## 생성·편집·빌드

project-store.mjs가 목록, ID→패키지명→프로젝트 루트 해석, 저장, 복제, 복원, 이관과 잠금을 담당한다. 자산·미리보기 조회는 projectId를 요구하며 검증된 해당 프로젝트 경로에서만 읽는다. 경로·메타데이터 불일치와 자산/프로젝트 경로의 심볼릭 링크는 거부한다. 이미지 읽기·미리보기 캐시 사용 전·백업 생성 시 내용 해시를 확인한다.

공통/개별 원본, 말풍선 첫/연속 본체·캐릭터, typed overrides와 기하를 보존한다. 미리보기·새 빌드는 프로젝트 폴더에 생성한다. Android 빌드 출력 루트와 전역 키/bindings 루트를 분리했으므로 이관 후에도 동일 ID/인증서의 versionCode가 이어진다. 기존 전역 builds의 목록/다운로드는 호환 조회한다.

이미지 리소스와 테마 정보 패널에서 프로젝트 경로, 폴더 열기를 제공한다. 이미지 패널은 자산 수/용량, 현재 사용하는 원본과 보관 원본, 각 이미지의 슬롯·출력 사용처를 보여 준다. 다른 프로젝트의 이미지는 이 목록에 섞이지 않는다.

## 백업과 복원

다운로드 파일명은 테마명·패키지명·한국 시간·고유 ID를 포함한다. 사용자가 백업하면 같은 ZIP을 프로젝트 backups에도 보관한다. ZIP에는 다음 파일만 포함한다.

```text
<packageId>--backup-<한국시간>-<백업 UUID>/
  backup.json
  theme.json
  assets/<sha256>.png
```

manifest는 포맷/버전, 프로젝트 식별과 파일별 해시/크기를 기록한다. 개인키·비밀번호·세션·bindings·빌드·캐시·과거 백업과 참조하지 않는 이미지는 포함하지 않는다. signingKeyId는 null이며 키는 별도 복원한다. 자산 해시 또는 manifest 불일치면 백업/복원을 거부한다. 백업 생성 시 복원 한도를 초과하는 ZIP도 저장하지 않는다.

기존 루트 theme.json + assets 형식도 읽는다. ZIP의 central directory를 먼저 검사해 중복 이름과 경로 문제를 거부하고 CRC·파일 수/크기·이미지 형식·참조 무결성을 검증한다. 최종 ID/패키지 중복 확인은 저장소 큐 안에서 수행한 후 준비 폴더를 등록하므로, 중복/조작 ZIP 때문에 기존 프로젝트나 공용 자산을 덮어쓰지 않는다.

같은 ID 또는 패키지명의 백업을 선택하면 기존 프로젝트 열기 / 새 프로젝트로 가져오기 / 취소를 제공한다. 새 프로젝트는 새 UUID·패키지명과 독립 파일을 사용하며 원본을 유지한다. 같은 프로젝트 덮어쓰기 복원은 제공하지 않는다.

## 기존 데이터 이관과 복구

서버/CLI가 저장소를 열 때 구형 projects/<id>.json을 인식한다. 원본은 그대로 두고 참조 그림을 준비 폴더에 복사·해시 검증한 뒤 패키지명 폴더로 등록한다. 새 폴더가 완료되면 해당 ID의 구형 JSON은 목록에 중복 표시하지 않는다. 이후 편집은 새 theme.json에만 저장한다.

이관 실패 시 해당 원본을 유지하고 시작 오류로 알린다. 이번 호출이 만든 미완료 준비 폴더만 정리한다. 이전에 중단된 준비 폴더는 보존한 채 원본에서 다시 이관할 수 있으며, 정상 완료 폴더는 재실행해도 다시 이관하지 않는다. 완료 표시 없는 사용자 폴더나 소유 ID가 다른 폴더를 자동 채택/덮어쓰지 않는다.

원본 JSON·공유 assets·기존 builds·전역 backups·키·bindings는 자동 삭제하지 않는다. 구형 원본은 복구용이며 새 저장 데이터와 동기화하지 않는다. 구형 앱을 새 저장소와 동시에 사용하지 않는다. 새 서버/CLI는 저장소 실행 잠금을 사용하고 살아 있는 기존 서버가 있으면 이관을 거부한다. stale lock은 소유 프로세스가 종료됐음을 확인하고 재획득한다. 기존 런처는 구버전 서버를 재사용하지 않고 종료·재실행을 안내한다.

`node src/cli.mjs migrate`로 저장소 점검/이관을 실행할 수 있다. 정상 종료 시 잠금을 해제한다. `build`는 이관된 theme.json 또는 구형 프로젝트 JSON 경로를 해석하고, 외부로 풀어 둔 프로젝트는 인접 assets를 사용한다. 서명키는 workspace의 별도 저장소에서 잠금 해제한다.

이번 현재 작업 폴더의 실제 .data는 실행 서버를 확인한 뒤 재시작해 두 프로젝트를 이관했다. 원본 보존 기록과 설정 사본은 .data/backups/storage-transition-2026-10-25T16-27-31-393Z에 있다. 디스크 원본 7개 파일의 내용 또는 키 파일 메타데이터가 유지됨을 확인했고, 기존 인증 링크를 유지한 새 서버가 실행 중이다. 실제 사용자 테마 화면 캡처나 개인키를 검증 보고서로 복사하지 않았다.
