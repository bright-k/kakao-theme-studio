# 0.9.0 공통 정책·캐릭터 여백·선택 여유

> 본체 과대 생성 문제는 후속0.9.1에서 다시 확인하고 보완했다. 현재 크기 계산은 REVIEW-0.9.1.md를 따른다.

구현일: 2026-10-26. 앱/컴파일러0.9.0, schemaVersion1과 프로젝트 저장·백업 포맷은 유지한다.

## 첫 말풍선과 캐릭터

캐릭터가 있는 첫 상태의 보낸/받은 말풍선에서 사용자 여백 변경이 상쇄되는 문제를 수정했다. 이전 계산은 내용 여백의 합을 고정 영역 크기에 맞추면서 사용자가 더한 padding도 그 안에 흡수했다. 이제 캐릭터 보호 공간과 글자 padding을 더하고, 합성 본체의 평평한 부분만 가로/세로 확장한다. 따라서 padding이 달라지면 생성 크기/내용 여백도 반응하고 캐릭터·모서리는 고정 크기를 유지한다. bodyHeight를 사용해 원래64×56 본체와 확장 출력을 구분한다.

작은 캐릭터에서 가이드가 본체의 모서리에 걸리지 않도록 중심 구간을 제한했다. 공통/첫 상태에서 상속하는 입력은 현재 값으로 동기화하고, 개별 모서리 우선과 공통 연결 버튼을 표시한다. 이미지 본체는 원본 모양을 따르며, 개별 출력·수동 가이드를 자동 삭제하지 않는다. 공통 본체로 승격할 때는 늘림 띠만 제거해 원래 그림 픽셀을 보존한다.

## 공통 정책 전수 검토

39개 의미별 공통 색상 정책을 추가했다. 하단 안내/라이트 배너, 공통 버튼3상태, 앱 내부 알림, 전달 안내/이동, 목록/헤더/탭, 채팅 배경·입력창, 잠금화면·키패드를 포함한다. 세부 매핑과 제외 근거는 [COMMON-COLORS.md](COMMON-COLORS.md), 기계 판독 결과는 common-color-coverage.json이다.

공통 정책은 iOS 색상·연관 투명도48개와 Android 색상39개에 연결한다. 나머지 iOS6개/Android10개도 기존 말풍선 글자색 공통 정책 또는 위치·상태가 다른 플랫폼 전용으로 분류했다. Android의 이름/내용, 상태 공유처럼 실제 출력 슬롯이 하나인 경우 공통 입력을 묶고 iOS만 개별 세분화를 허용한다. iOS 구역 구분선과 Android 목록 항목 구분선처럼 다른 역할을 억지로 묶지 않는다. 공통 이미지51개/출력146개는 유지한다.

기본값도 같은 팔레트 역할로 통일하며, optional commonColors의 지정값을 그 위에 적용하고 기존 플랫폼 overrides를 최우선으로 유지한다. 화면 공통색 편집은 palette를 변경하지 않는다. 공통 지정색은 불투명 #RRGGBB이고 자동 목록/메뉴 배경의 투명도는 양 플랫폼에 같은 기본값을 매핑한다. 자세한 alpha/Android ARGB는 플랫폼 예외로 유지한다.

화면별 공통 패널에서 한 번 설정하고 iOS/Android 세부 버튼으로 기존 catalog-editor에 이동한다. 예외 수와 현재 출력 차이를 표시하며 재연결/공통 자동값 복귀와 실행취소를 지원한다. validation·visualRevision·복제·이력·ZIP·CSS/XML·배경 PNG·미리보기·실제 APK/ktheme에 연결했다. 서버의 새 정적 모듈 경로도 등록했다.

## 선택 표시

시각적인 선택 테두리에5CSSpx 여유를 주고 라벨을 띄웠다. 화면 밖으로는 자르며 실제 hit와 생성/내보내기 Canvas에는 여유나 테두리를 넣지 않는다. 배너·버튼 장면의 설명용 전체 화면 backdrop은 선택 영역과 목록에서 제외한다.

## 검증과 경계

검증 결과는 VERIFICATION.md의0.9.0 항목을 따른다. 테스트는 격리한 .test-data를 사용하며 실제 카카오톡 적용은 사용자가 확인한다. deviceVerified는 false를 유지한다. 기존 개별 설정은 유지되고, 미지정 자동 색상은 새 공통 정책을 따르므로 두 플랫폼의 기본 표시 차이가 줄어든다. 기존 APK/ktheme는 다시 생성해야 반영된다.
