# 0.2.0 지원 범위 검토와 개선

검토일: 2026-10-25. 사용자의 전체 수정 범위·제작 효율·잠금화면 리소스 요청에 따라 구현했다.

## 검토 결론

0.1.0은 기본 팔레트 10색과 공통 이미지 11개를 중심으로 한 MVP여서 모든 항목을 개별 조정할 수 없었다. 실제 공식 샘플·가이드와 대조한 결과, 출력 이미지 슬롯 30개도 빠져 있었다. 대표적인 누락은 태블릿용 배경/아이콘, 지역별 로컬 탭, 스플래시, 탭 배경 9-patch다.

0.2.0은 **확보한 26.9.0 공식 샘플과 명시된 가이드 추가 항목**을 카탈로그로 고정하고 개별 편집·생성·검증하도록 바꿨다. 지원 항목표는 SUPPORT-MATRIX.md, 기계 검증 결과는 coverage-before.json과 coverage-after.json에 있다. 다른 카카오톡 버전과 비공개 항목까지 포괄한다는 뜻은 아니다.

## 지원 범위

| 영역 | 0.1.0 | 0.2.0 |
|---|---|---|
| iOS 속성 | 대표 팔레트로 일괄 치환 | 105개 등록: 메타데이터, 이미지 연결, 개별 색·투명도·말풍선 인셋/늘림 |
| Android 색상 | 공통 10색에 종속 | 49개 개별 설정, RGB/ARGB |
| 이미지 | 공통 11개 입력, 일부 출력 누락 | 82개 논리 그룹 / 146개 배율·화면별 출력 슬롯 |
| 비밀번호 표시 | 공통 기본 도형, 직접 편집 UI 없음 | 1~4번 입력 전·후 이미지 8개 개별 등록 |
| 키패드 | 일부 공통 색상 | iOS 눌림 이미지, 양쪽 배경·숫자·안내 색, Android 누름·패턴 연결선 색 |
| 상태·기기별 이미지 | 선택 상태를 일부 자동 생성 | 일반/선택, 첫/연속, 배율·태블릿 등 각 출력에 별도 이미지 지정 |
| 제작 재사용 | 새 프로젝트·백업 | 새 ID로 테마 복제, 실행취소/다시실행 |
| 일괄 작업 | 파일 하나씩 등록 | 이름 매칭 일괄 등록, 전체 리소스 템플릿 ZIP, 누락·미일치 보고 |

146개는 공식 샘플 PNG 127개 + 가이드 명시 추가 6개 + iOS @2x 보완 13개다. 서로 다른 디자인 146종이라는 의미는 아니다. iOS 66개 수치 속성(색·투명도·인셋·늘림)은 세부 편집기에 있고, 이미지 속성은 해당 이미지 그룹으로 연결된다. 이름·제작자·버전·URL·모드는 테마 정보에서, ID는 자동 관리·복제 방식으로 다룬다.

## 정확성 개선

- 주석이 selector와 중괄호 사이에 있으면 기존 정규식이 `FeatureStyle-Primary`를 건너뛰던 문제를 제거했다. 카탈로그 기반으로 모든 선언을 직렬화한다.
- 상태별 색상을 공통색 하나로 강제하던 구조에 플랫폼별 재정의를 추가했다.
- Android 8자리 색상은 ARGB, 웹 Canvas는 RGBA라는 차이를 명시적으로 변환했다. 출력 PNG와 XML도 같은 색을 사용한다.
- Android 미리보기는 생성된 9-patch의 늘림 구간과 내용 영역을 읽는다. 복수 늘림 구간도 분배해서 표시한다.
- 선택 말풍선은 iOS의 실제 선택 이미지/글자색을 사용한다. Android에서 지원되지 않는 선택 이미지를 밝기 조절로 가정하지 않는다.
- 비밀번호 입력 표시 이미지 8개를 양 플랫폼의 실제 파일에 각각 매핑한다. 키패드 눌림 이미지도 실제 생성 파일을 읽는다.
- 배경 이미지를 끄면 배경색으로 검토·생성할 수 있고, 이미지 사용 시 크롭 초점을 조정한다.
- 리소스 등록 후 직접 설정 개수와 미리보기가 갱신되게 했다.

## 효율 개선

- 공통 팔레트/이미지를 기본값으로 사용하고 필요한 항목만 세부 재정의한다. `자동` 또는 `공통값으로 복귀`로 되돌릴 수 있다.
- 원본 리소스 템플릿을 현재 디자인으로 내보내므로 파일명을 외울 필요 없이 편집 후 일괄 등록할 수 있다. 유효한 .9.png는 원본 가이드를 유지하며 일반 PNG를 9-patch 슬롯에 등록하면 가이드를 생성한다.
- 색상·슬라이더 연속 조작을 묶어 실행취소하며 새 테마 복제 시 디자인·리소스를 보존하고 고유 ID와 배포 버전을 새로 만든다.
- 메타데이터 수정 시 이미지 변환을 재사용한다. 이번 호스트 측정값은 coverage-after.json에 기록했고, 픽셀/파일 해시가 그대로인지 검사했다. 고정 성능 보장값은 아니다.
- 브라우저도 이미지 해시가 같으면 기존 비트맵을 재사용한다. 미리보기 revision에 컴파일러 버전을 포함해 이전 출력 캐시와 섞이지 않게 했다.
- 프로젝트 백업에 플랫폼별 설정·리소스 참조·원본 9-patch 플래그를 포함하며 개인키는 계속 제외한다.

## 검증과 남은 경계

18개 단위·회귀 테스트, 기존 브라우저 제작 흐름, 확장 편집 흐름, 모든 리소스 템플릿의 재등록, 실제 APK 컴파일·서명·키 복원·다른 키 거부를 확인했다. 확장 APK도 Android 13 에뮬레이터에서 설치·실행·업데이트를 확인했다.

실제 iPhone 및 카카오톡 내부 테마 인식·적용은 아직 미검증이다. 슬롯을 생성할 수 있는 것과 특정 OS/카카오톡에서 표시되는 것은 구분한다. 스플래시는 가이드상 Android 12 미만 대상이며, 가로/태블릿 파일도 출력하지만 해당 기기의 실제 화면은 검증하지 않았다. 레이아웃·폰트 파일 교체 등 가이드 밖의 변경은 지원한다고 표시하지 않는다.

Keychain, 빌드 취소·재시작 복구, 프로세스 간 버전 락, 캐시 자동 정리는 후속 과제다. 이번에는 사용자 요청에 직접 관련된 수정 범위와 반복 제작 흐름을 우선했다.
