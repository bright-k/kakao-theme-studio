# 0.12.0 에셋·프로젝트 정리

이미지 리소스 패널에 `미사용 에셋 정리`와 `보관함`을 추가했다. 정리 대상에는 현재 저장 설정, 편집 중 설정, 실행취소·다시실행 스냅샷에서 모두 참조하지 않는 원본만 표시한다. 공통/최종 출력/플랫폼 본체·캐릭터, 비활성 모드와 대체용 원본도 참조로 보호한다. assetHashes의 과거 검증 기록만으로는 사용 중으로 판정하지 않는다.

목록은 원본 썸네일·경로·용량, 전체/선택 개수와 합계 용량을 표시한다. 선택 후 `선택한 에셋 보관함으로 이동`을 누르면 프로젝트 내부 asset-trash/<작업UUID>/assets/...로 옮긴다. 같은 보호 기준의 `영구 삭제`도 제공한다. 선택 개수·용량과 복구 불가 안내를 확인하고 실행한다. 보관함에서도 영구 삭제할 수 있다. 자동 정리는 제공하지 않는다. 보관함에서 썸네일·원래 경로·용량·시각을 확인하고 선택 복구한다. 복구는 원래 경로와 바이트를 돌려놓으며 디자인 설정에 자동 적용하지 않는다.

assetReferences를 브라우저/서버 공통 순수 모듈로 분리했다. ProjectHistory.referencedAssets는 현재 커서 뒤의 redo와 앞의 undo를 모두 포함하고, 폐기/한도 초과 스냅샷만 제외한다. 편집기는 참조 집합 변경·프로젝트 전환·포커스 복귀 시 세션별 보호 참조를 서버에 보낸다. 실행 중 서버에 등록된 다른 탭의 기록도 합산한다. 순번으로 오래된 요청을 무시하고 정상 페이지 종료 시 해제한다. 종료 통지가 누락된 탭은 서버 재시작까지 보수적으로 보호할 수 있다. 편집 기록 자체는 기존처럼 브라우저 메모리에 있으며 서버 재시작 뒤 기존 탭은 새로고침해 사용한다.

목록 조회와 이동은 저장소 transaction 안에서 현재 저장 설정/요청 설정/등록된 기록을 다시 합산한다. 조회 후 참조가 생긴 원본이 선택에 있으면 이동 전체를 거절하고 목록을 새로고침한다. 경로·프로젝트 소유·해시·심볼릭 링크를 검증하며 다른 프로젝트·키·빌드·백업·미리보기 캐시는 건드리지 않는다.

assets/index.json과 theme.assetHashes는 유지한다. 옮긴 버전 번호를 새 업로드가 재사용하지 않으며 원래 경로 복구가 가능하다. 작업 manifest를 먼저 임시 파일→rename으로 기록한 뒤 원본을 옮긴다. 중단 뒤에는 실제 보관 파일만 표시해 이동된 부분을 복구할 수 있다. 복구는 기존 원본을 덮어쓰지 않고, 같은 바이트가 이미 있는 경우에만 중복 보관본을 해제한다. 손상되거나 충돌한 원본은 보존하고 오류를 표시한다.

보관함 이동은 폴더 정리이며 같은 디스크의 전체 사용량을 줄이지 않는다. 최종 APK/ktheme와 프로젝트 백업 ZIP에는 보관함을 포함하지 않는다. 출력 정책·원본 이름·저장/백업 포맷은 그대로이며 앱/컴파일러는0.12.0이다. 정리 전후의 모든 생성 파일 바이트 동일성을 검증했다. 실제 사용자 에셋은 이동하지 않고 UI/서버만 반영한다.

## 프로젝트 관리

상단 `프로젝트 관리`는 작업 목록과 프로젝트 보관함을 나눠 이름/패키지명/폴더 용량/파일 수/수정 시각을 표시한다. 열기·이름 변경·복제·백업·보관함 이동·영구 삭제를 지원한다. 이름 변경·정리는 검토한 revision과 현재 저장본이 같을 때만 수행한다. 생성 중/대기 작업이 있는 프로젝트는 정리를 거부한다.

보관은 `<data>/project-trash/<uuid>/project/`로 프로젝트 폴더 전체를 옮기고 manifest를 유지한다. 원본·에셋 보관함·미리보기·빌드·프로젝트 내부 백업을 함께 복구하며 프로젝트 ID/패키지명/서명키 참조는 같다. 전역 keys/bindings와 구형 공용 이관 원본은 이동·삭제하지 않는다. 영구 삭제는 프로젝트 폴더 내용 전체를 제거하므로 범위를 안내하고 별도 실행한다.

정리한 ID와 패키지명을 기록해 구형 projects/<id>.json의 자동 재이관과 다른 탭의 오래된 PUT 저장에 의한 부활을 차단한다. 독립 신규 프로젝트에는 다른 패키지명을 사용한다. 보관함에 있는 프로젝트는 보관함에서 복구하거나 ZIP을 새 프로젝트로 가져온다. 영구 삭제 뒤 사용자가 별도로 가진 유효한 백업을 명시 가져오면 원래 ID/패키지명으로 등록할 수 있으며 기존 전역 서명 연결을 보존한다. 서버 재시작 때 활성 폴더의 소유 정보와 정리 기록을 대조한다.

현재 작업을 정리하면 남은 프로젝트를 선택하고, 모두 정리하면 빈 상태에서 새 프로젝트·백업 열기·보관함 복구를 제공한다. 정리 이력이 있는 빈 저장소에는 기본 프로젝트를 자동 재생성하지 않는다. 프로젝트 관리 모달 중 전역 실행취소 단축키를 막는다.

단위76개와 에셋/프로젝트 전용 브라우저·기존 생성/저장소/에디터 회귀가 통과했다. 실제 APK/ktheme 검증도 통과했다. 상세 근거는 VERIFICATION.md다. 실제 사용자 프로젝트·에셋은 테스트로 이동/삭제하지 않았다.
