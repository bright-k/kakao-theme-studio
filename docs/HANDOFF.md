## 캐릭터 모서리 겹침·위치 세부 조정 검토 (2026-10-26, 미구현)

- 사용자는 첨부처럼 캐릭터가 말풍선 좌/우 위 모서리 바깥에 걸치고 일부 겹쳐 자연스럽게 연결되는 배치를 검토해 달라고 요청했다. 이번 작업은 코드/규격 검토이며 제품 코드·버전·실행 서버·사용자 프로젝트를 변경하지 않았다. 첨부만으로 해당 테마의 내부 가이드나 실제 구현을 확정하지 않는다.
- 현재 design-editor/resources 검증은 gap/offset을0~24로 제한한다. bubble-model은 header=size+gap, decoration.y=0이고 본체는 y=header라서 gap0도 정사각 캐릭터 영역과 본체를 분리한다. offset은 본체 안쪽 여백만 허용한다. composeBubble의 PNG.bitblt는 겹치지 않는 조건을 전제로 한다. 따라서 UI 입력 범위만 음수로 바꾸면 투명 픽셀이 본체를 지우고 가이드/선택/승격도 어긋난다.
- 지원 권장안: 좌/우 위 모서리를 기준으로 기존 크기와 분리된 signed 가로 이동(바깥/안쪽), 세로 간격/겹침 깊이, 앞/뒤 합성 순서를 제공한다. 기본은 기존 배치 그대로다. 필요하면 원본을 보존한 채 투명 여백을 제외한 정렬 옵션을 추가한다. 시각 드래그와 숫자 입력은 같은 값을 편집하고, 안전 범위를 표시한다. 중앙 자유 배치보다 모서리 고정을 먼저 지원한다.
- iOS/Android 공통 bubbleDesign에서 보낸/받은·첫/연속별 배치를 관리하고 출력별 이미지·가이드 예외 우선순위는 유지한다. 향후 플랫폼별 배치 수치 예외가 필요하면 공통값 상속→명시 예외 구조로 추가하며 두 개의 독립 기본 정책을 만들지 않는다. 현 카탈로그에 캐릭터 독립 런타임 위치 속성은 없으므로 최종 PNG 합성으로 구현한다.
- 기하 계약: bodyRect와 decorationRect를 별도로 정의하고 합집합을 출력 경계로 옮긴다. 바깥 돌출은 투명 캔버스/출력 내용 여백에 반영하되 본체 내부 글자 여백과 본체 높이에 더하지 않는다. 캐릭터 전체를 가로·세로 늘림 띠 밖의 고정 모서리에 둔다. 겹침이 상단 고정 영역이나 글자 여백을 넘으면 제한/안내하며 몰래 본체를 키우지 않는다. 큰 캐릭터의 최소 가로 공간과 앱의 인접 메시지·프로필 간격은 별도 제약이다.
- 합성/원본 계약: 반투명 알파를 정상 합성하고 앞/뒤 순서를 적용한다. 공통 본체 승격은 합성 PNG를 잘라 쓰지 말고 장식 전 본체를 다시 생성해야 한다(겹친 장식이 원본에 남는 것을 방지). 원본 그림의 불변 버전, resourceOverrides/resourceGeometry 우선, iOS 수동 가이드 보정과 첫/연속의 공유 글자 여백 제약을 유지한다. Canvas hit/nineRect/컴포넌트 장면도 새 사각형을 공유한다.
- 계산 검토만 실행했다: radius18/padding13,7/size32/gap0에서 현 header32. 가상 겹침6이면 header26/세로 stretch46이고 캐릭터 하단32가 늘림 띠 밖이며 본체 위 여백12 안에 겹침이 들어간다. 음수 gap/offset은 현재 검증에서 거부됨을 확인했다. 이는 설계 가능성 확인이며 합성/출력/실기기 지원 완료 검증이 아니다.
- 구현 시 필요한 검증: 양 플랫폼·배율·좌/우·첫/연속·색상/이미지·작고 큰 캐릭터·한 글자/긴/여러 줄에서 캐릭터 픽셀 크기/모서리 상대 위치와 본체 크기 불변, 반투명 앞/뒤 겹침, 글자 충돌/안전 범위, 원본 승격, 수동 가이드·출력 예외, 선택/undo/복제/ZIP/캐시. compilerVersion 갱신과 실제 APK/ktheme 통합 검증 후에 제품 지원으로 기록한다. 실제 카카오톡 적용은 사용자 확인 범위를 유지한다.
- 공식 근거: [Android NinePatch](https://developer.android.com/develop/ui/views/graphics/drawables#nine-patch)는 고정/늘림 영역과 내용 영역을 분리한다. [Apple capInsets](https://developer.apple.com/documentation/uikit/uiimage/capinsets)는 고정 끝 영역을 정의한다. 이 일반 이미지 규칙과 현 출력 구조를 근거로 가능한 구현 방식이라고 판단했으며, 카카오톡의 특정 버전 동작 보증은 아니다.

## 검증 근거

## 데이터 보존

사용자 데이터는 .data다. 프로젝트, 키, bindings, 빌드 결과를 삭제하거나 테스트 데이터로 덮어쓰지 않는다. 이전 schemaVersion 1 프로젝트는 새 필드가 생략돼도 동작한다. 서버 코드 업데이트는 재시작이 필요하고 키의 잠금 해제가 다시 필요하다. 테스트 키가 들어 있는 .test-data는 배포·커밋하지 않는다. examples의 APK와 ZIP에는 개인키를 넣지 않았다.

## 구조와 수정 주의

- catalog.mjs와 profile-26.9.0.json이 속성/리소스 등록을 담당한다. 공식 템플릿 식별자와 카탈로그 일치 테스트가 있다.
- styles.mjs는 typed 재정의를 CSS/XML로 직렬화한다. resources.mjs는 완성 이미지, 9-patch 가이드, 옵션과 전체 지원 범위를 검증한다.
- editor-service.mjs는 전체 리소스와 미리보기 파일 메타데이터를 연결한다. public/catalog-editor.js, history.js, preview-renderer.js가 편집·복원·출력 리소스 검토를 담당한다.
- 출력 규칙이 바뀌면 COMPILER_VERSION을 갱신한다. 미리보기·키 관련 입력을 셸 명령 문자열에 넣지 않는다.
- Android resources.arsc는 STORE 및 4바이트 정렬을 유지한다. 서명 후 APK를 수정하지 않는다.
- 카카오 캐릭터 PNG를 기본 자산으로 복사하지 않는다. 프로필의 기준 범위·출처와 실제 적용 확인 여부를 유지한다.

## 남은 작업

최우선은 준비된 실제 카카오톡/iPhone 테스트 환경에서 인식·적용·화면 차이를 검증하는 일이다. 새 버전 프로필 추가는 별도로 검증한다. Keychain, 작업 취소·재시작 복구, 프로세스 간 버전 락, 캐시 자동 정리는 아직 구현하지 않았다. 한 dataRoot에서 서버와 CLI를 동시에 빌드하지 않는다. 이미지 업로드는 PNG/JPEG/WebP이며 외부 SVG와 임의 CSS/XML 삽입은 지원하지 않는다.

복제는 새로운 ID와 초기 버전으로 만든다. 동일 ID의 프로젝트 ZIP을 다시 가져오면 기존 프로젝트를 열도록 안내한다. 미리보기는 자체 화면으로 글꼴·배치의 픽셀 일치를 보장하지 않는다.

## 0.3.1 미리보기 말풍선 경계

사용자가 확대 캡처에서 말풍선 분할 경계의 가는 밝은 선을 보고했다. 원본 PNG 내부는 균일했다. drawNine은 임시 Canvas의 정수 픽셀 경계에 조각을 합친 뒤 목적지에 한 번 그린다. 분할 경계의 소수점 좌표와 반투명 조각 중첩을 피한다. 생성 PNG/9-patch/패키징은 변경하지 않아 compilerVersion 0.2.0을 유지했다. test/preview-seams.mjs는 불투명/반투명·iOS/Android 배율·다중 늘림 구간의 내부 픽셀을 검사한다.

## 0.4.0 상태·원본·기하 편집

- 상태 미리보기: 0~4자리 비밀번호/누른 숫자, 전체 8개 탭, Android 프로필 1~3/전체 원본, 첫·연속 말풍선과 iOS 선택 상태, 버튼/목록 기본·누름·선택, 기본/라이트 배너. 대표 레이아웃이며 실제 기기 검증은 아니다.
- 실제 출력별 source 메타데이터와 전체 sources 색인으로 적용 원본·기본 생성·비활성화·재정의·가이드 출처를 안내한다. src/provenance.mjs와 전체 픽셀 대조 테스트가 근거다.
