# 0.13.0 제작 흐름·HEX·단색 배경

캐릭터가 있는 첫 말풍선, 배경색 설정, 색상 입력과 실제 제작 흐름을 검토했다. 사용자 저장소의 마지막 기존 결과는 compiler0.7.0 생성본으로 확인했다. 이후의 고정 캐릭터 크기·본체 높이·Android 내용 가이드 보정은 기존 파일에 반영되지 않는다. 첨부 화면만으로 실제 카카오톡 배치의 모든 원인을 확정하지 않으며 기존 파일·사용자 설정은 변경하지 않았다.

현재 코드에서도 iOS 수동 가이드의 보호 누락을 확인했다. 수동 늘림이 캐릭터를 통과하거나 내용 여백이 본체 위에 놓이면 합성 그림/본문이 어긋날 수 있었다. Android에서 쓰는 resolveComposedGuides를 iOS 출력에도 적용해 실제 본체·고정 모서리·캐릭터를 보호한다. 생성만으로 저장 overrides를 수정하지 않는다. 최종 출력 이미지 예외는 기존 가이드 정책을 유지하며, 세부 시각 편집은 실제 적용값을 표시하고 입력값도 보호 범위로 제한한다. Android의 내용 여백과 정렬 영역은 별개라는 [공식 API 설명](https://developer.android.com/reference/android/graphics/drawable/NinePatchDrawable)을 참고하되 실제 카카오톡 내부 레이아웃 검증과 구분했다.

배경은 이미 이미지 비활성화와 색상 출력을 지원했다. 이제 기본 화면·대화방·잠금화면·탭의 원본 패널에서 이미지/색상만 사용을 바로 고른다. 단색 HEX를 바꾸면 양 플랫폼 이미지를 끄고 commonColors에 색상을 저장한다. 원본·크롭·최종 이미지 예외는 보존하며 이미지 모드로 복귀할 수 있다. 플랫폼 색상 예외는 계속 우선하고 개수를 표시한다. 등록 이미지가 없는 이미지 모드는 기존 생성기가 올바른 크기의 단색 PNG를 만든다. 단색으로 전환한 채팅/전달 장면이 main 색상을 대신 표시하던 미리보기 오류도 chat 색상으로 수정했다.

모든 색상 견본은 브라우저 native RGB/HSL 대화상자 대신 공통 HEX popover를 연다. HEX 입력과 색조·채도·밝기 슬라이더, 키보드·Escape를 지원하며 말풍선 본체/글자색에도 직접 HEX 입력을 추가했다. Android #AARRGGBB의 AA는 견본에서 RGB만 바꿀 때 보존한다. 잘못된 HEX는 최신 유효값으로 돌아간다. 기존 연속 입력 큐·실행취소·프로젝트 소유 검사와 입력 포커스를 유지한다.

생성 결과의 compiler 또는 정확한 프로젝트 revision이 현재와 다르면 재생성 안내를 표시한다. 현재 편집 상태의 SHA-256을 비교하므로 미리보기 갱신 전 메타데이터/서명키 변경에도 이전 프레임을 기준으로 잘못 판단하지 않는다. 실제 새 결과는 곧바로 이전 결과로 표시하지 않는다.

앱/컴파일러는0.13.0이며 저장/백업 포맷, 공통 원본51·플랫폼 입력16·공통색39·출력146 범위는 유지한다. 새 단위3개와 간단한 별 캐릭터 테마의 브라우저 제작, 기존 회귀·실제 서명 APK/ktheme 검증을 수행했다. 자세한 명령·근거는 TESTING/VERIFICATION을 따른다. 사용자 데이터·키·기존 결과는 보존했고 실제 사용자 서버 재시작은 하지 않았다. 서버를 다시 실행하고 새로고침한 뒤 새 테마를 생성해야 반영된다. 실제 카카오톡/iPhone 적용 검증은 여전히 미완료이며 deviceVerified=false다.
