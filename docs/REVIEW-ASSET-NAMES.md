# 리소스 위치가 드러나는 원본 파일명 검토

검토일: 2026-10-26. 아래는 0.6.0을 기준으로 작성한 설계 기록이다. 사용자 승인 후 0.7.0에서 구현했다. 현재 계약과 검증은 [REVIEW-0.7.0.md](REVIEW-0.7.0.md)를 따른다.

## 권장안

프로젝트 디렉터리 안의 자산을 공통 원본과 플랫폼별 개별 원본으로 나누고, 파일명을 역할·상태·짧은 버전으로 구성한다. 해시는 파일명 대신 원본 메타데이터와 백업 manifest에서 무결성 검증용으로 유지한다.

```text
assets/
  common/
    chat/
      sent/
        first/body-v0001.png
        first/character-v0001.png
        continuous/body-v0001.png
        continuous/character-v0001.png
      received/
        first/body-v0001.png
    backgrounds/chat-v0001.png
    tabs/friends-normal-v0001.png
  ios/
    chat/sent/first/body-v0001.png
    chat/sent/first/2x/body-v0001.png
  android/
    chat/sent/first/body-v0001.9.png
```

이것은 편집 원본의 저장 이름 예시다. 최종 ktheme/APK 안의 공식 리소스 파일명·ZIP 구조·배율·9-patch 가이드는 그대로 유지한다. 원본 .9.png는 내부 저장 이름에서도 .9.png 확장자를 유지하고 일반 PNG 원본과 구분한다. 공통 역할과 실제 출력 이름은 SLOTS 및 카탈로그의 명시적 매핑으로 결정하며 임의 사용자 파일명을 경로로 쓰지 않는다.

## 플랫폼 접미사와 별도 경로 비교

후속 질문은 플랫폼별 원본에 _android/_ios 접미사를 붙이는 방식과 별도 디렉터리 방식의 비교다. 권장안은 assets/common, assets/android, assets/ios로 구분하고 같은 역할·상태에는 같은 이름을 쓰는 것이다. 플랫폼은 상위 경로로 이미 식별되므로 파일명에 다시 접미사를 붙일 필요가 없다. 업로드를 시작한 설정 대상이 공통인지 플랫폼 전용인지에 따라 앱이 경로와 파일명을 자동 배정한다.

공통은 같은 편집 항목의 두 플랫폼이 사용하는 원본을 뜻한다. 동일 그림을 서로 다른 편집 항목에 명시적으로 등록하면 역할별 독립 파일/버전을 만든다. 예를 들어 친구 탭과 채팅 탭은 같은 PNG라도 별도 파일로 보관하고, 각 항목 안에서 iOS/Android가 그 항목의 공통 원본을 참조한다. 기본/연속 대체 관계 등 명시적 상속은 유지한다.

플랫폼별 재정의는 현재와 같은 명시적 연결로 적용한다. 해당 출력의 전용 원본이 설정되어 있으면 이를 우선하고, 전용 설정이 없으면 연결된 공통 원본/기존 대체 정책을 사용한다. 앱에서 전용 설정을 해제하면 공통 연결로 복귀하며, 전용 그림 파일 자체를 임의 삭제했을 때 조용히 공통값으로 대체하지 않는다. 보관된 과거 버전 파일은 현재 적용 중인 설정으로 간주하지 않는다.

개별 배율/가로·태블릿 변형은 카탈로그의 실제 대상에 대응하는 추가 경로로 구분한다. 예시의 ios/.../body는 해당 항목의 iOS 배율 공통 원본, ios/.../2x/body는 특정 출력 원본을 의미한다. 실제 경로 분류/우선순위는 기존 resourceOverrides와 nativeNinePatch/resourceGeometry 및 비활성화 규칙을 보존해야 하며 폴더를 스캔해 임의 추정하지 않는다. 한 플랫폼에만 있는 상태를 반대 플랫폼의 가짜 출력으로 확장하지 않는다.

접미사는 파일 하나를 따로 전달할 때 식별하기 쉽다는 장점이 있지만 상태·배율·변형·버전까지 파일명에 몰리면 길어진다. 플랫폼 경로 분리는 관리 화면·버전 폴더·일괄 작업의 일관성을 유지하기에 적절하다. 이번은 경로 규칙 제안이며 실제 자산 이동이나 구현은 하지 않았다.

## 같은 원본의 여러 사용처와 변경 이력

공통 원본 하나는 여러 화면/플랫폼/배율/상태에 쓰일 수 있다. 공통 이미지 파일을 출력 146개 각각으로 확장해 저장하지 않고, 역할별 공통 원본을 필요한 출력들이 참조하도록 유지한다. 기본 프로필을 Android 추가 프로필이 대체 사용하거나 첫 말풍선을 연속이 대체 사용하는 경우도 자동 적용 관계를 유지한다. 대체값을 독립 파일처럼 실체화해 후속 공통 교체를 막지 않는다.

서로 다른 슬롯이 명시적으로 같은 원본을 참조할 때는 사용처를 모두 표시하고 교체 대상 슬롯만 새 버전을 참조하게 한다. 플랫폼별 개별 등록은 해당 출력 경로/배율의 재정의를 명시한다. 일괄 등록으로 같은 원본이 여러 출력에 지정된 경우 원본 버전과 적용 대상 목록을 함께 기록해 연결 관계를 잃지 않아야 한다.

단일 body.png를 계속 덮어쓰면 현재 ProjectHistory가 가진 과거 프로젝트 참조도 같은 파일을 가리켜 이전 그림 복원이 불가능해진다. 권장 기본은 body-v0001.png → body-v0002.png처럼 불변 버전을 만들고 현재 설정이 선택한 버전을 참조하는 것이다. 이전 버전은 자동 삭제하지 않는다. 임의 변경·백업 복원으로 같은 버전명이 이미 있으면 기존 파일을 덮어쓰지 않고 실제 내용과 참조를 검사해 새 버전을 배정한다. 버전 번호는 최신/적용 여부 그 자체가 아니며 실행취소 후 구버전이 현재 선택될 수 있다.

폴더에서 현재 그림만 body.png로 보고 싶은 경우 별도의 현재 버전 복사본/내보내기를 제공할 수 있지만 내부 참조와 이력 원본을 분리해야 한다. 이 경우 생성된 보기용 파일인지 편집 입력인지 명확히 안내한다. 단순한 파일명 개선 단계에서는 불변 버전 방식부터 구현하는 편이 변경 범위가 작다.

## 해시와 경로 검증의 변경 범위

현재 asset-store, core.validate의 assets 검사, resourceOverrides 검사, archive import와 info 목록은 assets/<64자리 해시>.png를 전제로 한다. 원본 파일명을 단순히 바꾸는 것만으로는 동작하지 않는다. 허용된 역할/플랫폼/출력 경로와 버전 패턴을 검증하고 원본 메타데이터의 SHA-256으로 실제 바이트를 확인하도록 함께 바꿔야 한다.

새 원본 메타데이터는 역할·버전·상대 경로·해시·크기·현재 사용처를 다루고 프로젝트별로 저장한다. 경로/내용의 무결성은 원본 읽기·미리보기·복제·백업/복원에서 검사한다. cache/visualRevision은 선택한 원본 버전과 실제 해시를 포함해야 한다. 과거 해시 이름 자산/백업도 계속 읽고 이관 시 원본과 참조 관계를 보존한다.

외부 이미지 편집기로 파일을 직접 수정하면 기존 무결성 정보와 달라진다. 파일명 개선과 외부 편집 반영은 구분하며, 직접 편집을 지원한다면 `폴더 변경 내용 불러오기`에서 형식·크기·원본 .9.png 가이드 검증 후 새 버전으로 등록하고 metadata/캐시/실행취소를 함께 갱신하는 명시적 흐름을 권장한다. 감지 즉시 원본 메타데이터를 조용히 덮어쓰는 방식은 채택하지 않는다.

## 이관 및 검증 기준

- 기존 프로젝트의 공통/개별 참조를 수집해 역할별 경로를 배정하고 준비 영역에서 복사·검증한 후 참조를 전환한다. 다중 사용 원본과 대체 적용 관계를 유지하며 기존 해시 파일은 보존한다.
- 새 파일명/경로/버전 충돌, 같은 원본의 여러 슬롯, 첫/연속/선택/배율·플랫폼 예외, 일반 PNG와 원본 .9.png, 이력/캐시/복제, 구형/신규 백업을 검증한다. 외부에서 이름만 바꾸거나 내용을 바꾼 경우의 오류/명시적 재등록도 확인한다.
- 현재 전체 출력 이미지 바이트/픽셀을 기준으로 이관 전후 동일성을 비교하고, 실제 APK/ktheme 빌드와 화면별/상태별 회귀를 수행한다. 저장 배치/백업/캐시 계약 버전은 실제 구현에 맞춰 갱신한다.

이번은 소스 계약을 확인한 설계 검토다. 기존 사용자 자산을 이름 변경·이동·삭제하거나 새 저장 형식을 구현하지 않았다.
