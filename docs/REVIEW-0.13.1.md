# 0.13.1 캐릭터가 있는 말풍선의 과도한 가로 여백

0.13.0까지도 캐릭터가 켜진 본체의 가로 fixed cap을 키우고 그 폭을 좌우 내용 여백으로 분배했다. 모서리18/여백13·7/캐릭터32 조건은 off19/20, on28/29였다. 따라서 같은 글자 폭80도 본체119→137이 됐다. 텍스트의 정렬 속성은 왼쪽이지만 불필요한 양쪽 여백이 가운데 정렬처럼 보이게 했다. 이전 완료 안내와 검증은 이 가로 문제를 놓쳤다.

이제 본체 폭·내용 여백을 캐릭터 없는 같은 설정과 동일하게 계산한다. 고정 캐릭터가 본체 모서리의 가로 cap보다 크면 automaticOutward로 모서리 바깥에 걸치고, 필요한 공간은 전체 PNG의 투명 여백과 출력 인셋에만 더한다. 같은 조건의 본체 여백은 켬/끔 모두19/20이다. 전체 PNG의 폭이 달라도 색이 칠해진 본체는 같은 내용에서 같은 폭이다. 캐릭터를 축소하거나 미리보기만 좁혀서 해결한 것은 아니다. iOS PNG/CSS와 Android9-patch 모두 같은 모델을 사용한다.

본문 모양/꼬리/명시 여백/최종 이미지 예외를 첫·연속에 다르게 설정한 경우 그 차이는 유지한다. 기존 파일과 저장 설정을 자동으로 바꾸거나 예외를 해제하지 않는다. 수동 iOS 가이드가 본체를 압축한 뒤 우측 캐릭터 위치가 이동하는 경우도 다시 제한한다. 승격은 실제 bodyRect의 원본을 보존한다.

채팅·전달 장면은 공통 messageLayout으로 측정·줄바꿈·위치를 정한다. 캐릭터가 밖으로 나온 전체 이미지가 화면 가장자리를 넘으면 전체 메시지를 안쪽으로 옮기고, 폭이 부족할 때는 줄바꿈을 조정한다. 캐릭터 공간을 다시 본문 padding에 넣지 않는다. 큰 캐릭터의 프로필 간격과 실제 카카오톡 레이아웃 차이는 기기 확인 대상이며 편집 UI에도 안내한다.

새 검증은 같은 내용의 켬/끔을 직접 대조한다. 최소 글자 폭1·한 글자·짧은 문장·긴 문장/여러 줄,12/32/72px 캐릭터, 양 플랫폼·쪽·첫/연속·기준 모서리·색상/이미지 본체의384쌍에서 실제 색 본체 폭·높이·글자 오프셋·줄바꿈이 같고 캐릭터 픽셀 크기도 유지된다. 기존 production 렌더러 검증도 폭·실제 색 픽셀 폭·글자 x 좌표를 추가했다. test-results/bubble-width-comparison.png와 bubble-content-width-report.json을 따른다.

앱/컴파일러는0.13.1이며 저장/백업 형식과 출력 슬롯은 유지한다. 실제 APK/ktheme 컴파일·서명을 포함한 최종 결과는 VERIFICATION에 기록한다. 실제 카카오톡 적용/deviceVerified는 별도이며 이 수정만으로 확인 완료로 바꾸지 않는다. 이전 APK/ktheme는 다시 생성해야 반영된다.
