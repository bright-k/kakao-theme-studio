# 0.10.1 짧은 디바운스와 연속 미리보기

사용자는 슬라이더를 움직이는 동안에도 화면이 갱신되기를 원했고, 후속으로 매 입력마다 생성하기보다 짧은 디바운스를 요청했다. 기존 입력 종료 후450ms 대기를80ms trailing debounce/최대160ms 대기로 바꿨다. 연속 입력도 최대 대기 안에 생성 요청을 내고, 조작이 멈추면 마지막 값으로 마무리한다. 생성·이미지 로딩 자체의 시간은 추가로 필요하다.

preview-queue는 생성 작업 하나와 최신 대기 스냅샷 하나만 유지한다. 완료된 중간 프레임도 표시해 연속 입력 중 화면이 멈추지 않는다. 프로젝트 객체/전환 epoch가 다르면 결과를 폐기하고 부분 로딩 이미지를 닫는다. 실행취소·프로젝트 전환의 명시 갱신은 디바운스 대기 없이 처리한다. 저장 디바운스350ms는 유지한다.

슬라이더·색상 선택기 외에도 유효한 HEX, 플랫폼별 수치/여백, 시각 가이드 숫자를 input 이벤트로 반영한다. 불완전한 HEX/수치 입력은 출력에 전달하지 않으며 blur 때 기존 검증을 유지한다. 활성 입력 DOM은 미리보기 갱신 때문에 교체하거나 덮어쓰지 않는다. 편집 콜백은 소유 프로젝트를 확인해 이전 입력의 change/blur가 새 프로젝트를 수정하지 않도록 한다. 연속 조절만 실행취소를 묶고 모드·앞뒤 등 개별 선택은 독립 기록한다.

미리보기는 실제 생성 PNG와 출력 속성을 계속 사용한다. 동일 본체 SVG·캐릭터 리사이즈·리소스 변환은 내용 해시/크기/옵션으로 캐시한다. 원본 검증을 건너뛰지 않으며 최종 출력146개의 바이트 동일성과 원본 변경 시 캐시 무효화를 검증했다. 캐시 한도와 원본 보존 정책을 유지한다.

본체 모양을 바꿀 때 공통 본체에는 가이드 테두리 없는 PNG를 등록하고 이미지 모드를 사용한다. iOS 늘림/내용 여백과 Android 가이드를 확인한다. Android 원본 .9.png는 플랫폼별 세부 이미지 교체에 등록해야1픽셀 테두리의 늘림/내용 가이드를 읽는다. 공통 이미지 업로드는 .9.png 가이드를 해석하지 않는다. 출력별 .9.png는 최종 말풍선을 교체하므로 공통 캐릭터 합성보다 우선한다. iOS는 PNG와 별도의 논리 좌표를 사용한다. 이 등록 방식은 이번에 변경하지 않았고 UI에 설명을 추가했다.

단위58개, 연속 포인터 조작·실제 Canvas 갱신·입력 포커스·최신값 저장·프로젝트 전환 경합과 기존 편집/제작 회귀 및 실제 APK/ktheme 통합 검증을 수행했다. 자세한 근거는 VERIFICATION.md다. 실제 카카오톡 적용은 사용자가 확인하며 deviceVerified=false다.
