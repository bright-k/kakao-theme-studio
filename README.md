# Kakao Theme Studio · Local

현재 버전: **0.12.0**. [지원 항목표](docs/SUPPORT-MATRIX.md)와 [개선 내역](docs/REVIEW-0.12.0.md)을 참고하세요.



프로젝트는 `.data/projects/<패키지명>/`별로 설정·이미지·미리보기·새 빌드·백업을 독립 보관합니다. `이미지 리소스` 또는 `테마 정보·서명`에서 실제 저장 위치를 확인하고 폴더를 열 수 있습니다. 이미지 패널에는 사용량과 원본별 사용처가 표시됩니다.

이미지는 업로드한 설정의 용도에 따라 `assets/common/chat/sent/first/character-v0001.png`처럼 자동 저장합니다. 같은 항목의 Android/iOS는 공통 원본을 함께 쓰며, 플랫폼별 교체는 `assets/android/` 또는 `assets/ios/`에 보관합니다. 서로 다른 항목에 같은 그림을 등록하면 각각 독립 파일이 생깁니다. 다시 업로드하면 새 버전을 만들어 실행취소용 원본을 유지합니다. 현재 적용 여부는 저장된 설정으로 결정되므로 보관 파일이 남아 있어도 해제한 예외가 다시 적용되지는 않습니다.

기존 해시 이름은 내용 검증 후 새 이름으로 복사하고 설정 참조를 전환합니다. 이전 파일과 이관 전 설정은 보존합니다. 폴더의 이미지를 직접 덮어쓰거나 이름을 바꾸면 검증 오류가 발생하므로 변경한 이미지는 앱에서 다시 업로드하세요.

상단 `프로젝트 관리`에서 프로젝트 이름·패키지명·용량·수정 시각을 확인하고 열기·이름 변경·복제·백업을 할 수 있습니다. 작업 목록에서 정리하려면 `보관함으로 이동`, 폴더 내용까지 지우려면 `영구 삭제`를 선택하세요. 프로젝트 보관함은 원본·설정·빌드·내부 백업을 함께 복구합니다. 전역 서명키와 앱 서명 연결 기록은 유지합니다. 모든 프로젝트를 정리하면 새 프로젝트·백업·보관함 복구를 선택하는 빈 화면이 표시됩니다. 별도로 보관한 백업 ZIP은 영구 삭제 후에도 명시적으로 가져올 수 있습니다.

`이미지 리소스 → 미사용 에셋 정리`에서 현재 설정과 실행취소·다시실행 기록이 참조하지 않는 원본만 확인할 수 있습니다. 썸네일·파일명·용량을 보고 선택해 복구 가능한 보관함으로 옮기세요. `보관함`에서 원래 위치로 복구할 수 있으며 설정에 자동 적용되지는 않습니다. 비활성 모드에 등록해 둔 이미지와 대체 원본도 보호합니다. 바로 지우려면 `영구 삭제`에서 개수·용량과 복구 불가 안내를 확인하고 실행하세요. 보관함 안에서도 영구 삭제할 수 있습니다. 자동 정리는 없고, 보관함 이동만으로 전체 디스크 사용량은 줄지 않습니다. 최종 테마와 프로젝트 백업 ZIP에는 보관함이 포함되지 않습니다.

백업 ZIP은 패키지명과 백업 시각별 폴더로 묶으며 이미지/설정 무결성을 확인합니다. 구형 백업도 가져올 수 있고, 이미 등록한 프로젝트는 기존 프로젝트 열기 또는 독립된 새 프로젝트로 가져오기를 선택할 수 있습니다. 기존 공유 자산과 원본 JSON은 복구용으로 보존하며 이관 뒤 자동 삭제하지 않습니다.

화면별 `공통 색상 · iOS와 Android`에서 같은 역할의 색상 39개를 함께 관리합니다. 하단 안내 배너·라이트 배너, 알림·전달 안내, 버튼 상태, 목록·입력창·잠금화면 등이 포함됩니다. 자세한 연결은 [공통 정책 검토표](docs/COMMON-COLORS.md)를 참고하세요. 기본값도 같은 팔레트 역할을 따릅니다. 기존 플랫폼별 재정의는 유지되며 `iOS 세부 설정`/`Android 세부 설정`에서 예외를 만들거나, `플랫폼 예외를 공통값으로 연결`로 해제할 수 있습니다. 공통 지정색은 불투명 색이고 투명도·Android ARGB는 세부 설정에서 조절합니다.

`캐릭터 크기·위치`에서 좌우 위치와 세로 간격·겹침을 슬라이더로 조정합니다. 현재 값과 이동 방향을 함께 표시하며, 음수 세로 값은 겹침이고 양수는 위로 띄움입니다. 앞뒤 순서를 고르거나 캐릭터 선택 후 미리보기에서 드래그할 수 있습니다. 위치·겹침 조정은 본체 크기와 내부 글자 여백을 바꾸지 않습니다. 글자·고정 그림을 보호하는 안전 범위만 허용합니다. 사용 여부만으로 본체 높이가 커지지 않습니다. 색상 본체는 모서리·꼬리에 필요한 크기로 생성해 과도한 빈 공간을 줄였습니다. 고정 캐릭터와 모서리를 담을 최소 가로 공간은 필요합니다. `공통 기준 본체 여백`에 최소 공간을 포함한 적용값을 표시합니다. 이미지 본체는 원본 모양을 따르며 개별 설정은 유지합니다.

공통 말풍선 본체 이미지를 등록하면 해당 본체가 자동으로 `등록한 이미지 사용`으로 전환됩니다. 기존에 등록했지만 색상 모드에 가려진 이미지는 `등록한 공통 본체 적용`을 누르세요. `iOS 본체·캐릭터`/`Android 본체·캐릭터`에서 본체 이미지만 교체해도 공통 캐릭터가 함께 합성됩니다. `공통 캐릭터 설정 따르기`를 해제하면 해당 플랫폼의 캐릭터 그림·사용 여부·크기·위치·겹침도 따로 조정할 수 있습니다. 본체와 캐릭터는 각각 공통 설정으로 되돌릴 수 있습니다. 연속 말풍선은 기존 연속 정책과 첫 번째 플랫폼 설정을 상속하며 별도 예외도 지원합니다. 늘림·여백은 `iOS 늘림·여백·최종 출력`/`Android 늘림·여백·최종 출력`에서 조정합니다. 기존 최종 이미지 예외는 계속 우선하며, 새 합성 방식을 쓰려면 해당 플랫폼의 `본체·캐릭터 합성 적용`을 누르세요. 원본은 보존됩니다.

Android 합성 말풍선은 개별 늘림·내용 가이드를 실제 본체 기준으로 변환합니다. 캐릭터와 모서리를 보호하고 글자가 본체 밖에 놓이지 않도록 적용 범위를 보정합니다. 기존 저장 설정과 원본 이미지는 보존하며 세부 편집에는 실제 적용 가이드를 표시합니다.

슬라이더와 유효한 값 입력은 **80ms 디바운스**로 미리보기에 반영하며, 계속 조작할 때도 최대160ms 안에 생성 요청을 시작합니다. 진행 중인 생성은 하나만 유지하고 다음에는 가장 최근 값을 처리합니다. 실제 생성 이미지의 처리 시간은 추가로 필요합니다. 저장은 별도로 자동 처리됩니다.

말풍선 모양을 직접 만들려면 가이드 테두리 없는 PNG를 공통 또는 플랫폼 본체로 등록하고 `등록한 이미지 사용`을 선택합니다. Android의 원본 `.9.png` 가이드를 그대로 쓰려면 `플랫폼별 적용 확인 → 세부 편집 → 이미지 교체`에 등록하세요. 개별 출력 이미지는 공통 캐릭터 합성보다 우선합니다. iOS는 일반 PNG와 별도의 늘림 지점·내용 여백을 사용합니다.

`배너·버튼`의 `적용 장면`에서 앱 안 새 메시지 알림, 메시지 전달 안내, 친구 추가·공통 버튼, 탭 위 안내 배너를 골라 실제 모바일 흐름에 가까운 화면에서 확인할 수 있습니다. 안내 문구로 어떤 설정이 어디에 적용되는지 설명하며, 휴대폰 시스템 알림과 앱 내부 알림을 구분합니다.

`플랫폼 보기`에서 iOS 또는 Android를 크게 볼 수 있습니다. 모바일 폭에서도 두 플랫폼을 선택해 검토하고, `수정할 부분` 목록으로 작은 요소에 접근할 수 있습니다. 선택 테두리는 그림의 좌표를 기준으로 약 5px 여유를 두어 표시하며, 글자나 아이콘에 너무 붙지 않습니다. 클릭 판정은 실제 요소 위치를 유지합니다. 배너·버튼 장면의 설명용 배경은 선택 대상에서 제외합니다.

화면 탭 아래의 별도 옵션 행에서 긴 메시지·선택 상태를 조절합니다. 옵션이 없는 화면에서도 탭과 다음 설정 행의 위치를 유지합니다.

미리보기의 배경·말풍선·캐릭터·프로필·탭 등을 누르면 해당 설정으로 이동합니다. 마우스를 올리면 선택 영역이 표시되고, `수정할 부분` 목록이나 `전체 설정 찾기`로도 이동할 수 있습니다.

`말풍선 본체와 캐릭터`에서 보낸/받은 쪽과 첫 번째/연속을 각각 설정하세요. 본체는 색상 또는 이미지로 만들고 캐릭터는 선택적으로 추가합니다. 연속 말풍선은 첫 번째 설정을 공유하거나 별도 본체·캐릭터 원본을 사용할 수 있습니다. 모드를 바꿔도 등록 이미지는 보존됩니다. 캐릭터가 있는 말풍선은 짧은 메시지에서도 지정 크기를 유지하도록 내용 여백을 자동 확보합니다. 큰 캐릭터는 짧은 말풍선에도 빈 공간이 필요합니다. 개별 늘림·여백 재정의는 기존대로 우선합니다.

펼쳐진 `공통 디자인 · 두 플랫폼`에는 원본 썸네일, 지원 플랫폼, 출력별 적용 상태가 나옵니다. 이미 개별 등록한 출력은 유지하며, 목록에서 선택한 출력만 공통 원본으로 연결할 수 있습니다. 새 기능 반영에는 서버 재시작과 브라우저 새로고침이 필요합니다.

상단 상태 선택에서 비밀번호 0~4자리·누른 숫자, 8개 탭, 프로필 변형/전체 원본, 첫·연속·선택 말풍선, 기본·누름·선택 버튼과 배너 변형을 검토할 수 있습니다. 상태 전환은 프로젝트를 수정하지 않습니다.

이미지 탭에는 현재 적용 원본과 출력별 재정의 여부가 표시됩니다. 공통 원본 목록에서도 실제 연결된 출력과 재정의로 가려진 출력을 확인할 수 있습니다.

말풍선 또는 Android 9-patch 이미지를 고르면 `늘림·여백 시각 편집`이 나옵니다. 초록/파랑 가이드는 늘림 구간, 주황 가이드는 내용 여백입니다. 핸들을 드래그하거나 숫자로 조절하세요. Android의 여러 늘림 구간을 추가·삭제할 수 있고, iOS는 1배수 논리 좌표를 사용합니다. 원본 가이드/공통 정책으로 복귀와 실행취소도 지원합니다.

왼쪽에서 화면을 선택하면 오른쪽 설정과 양 플랫폼 미리보기가 함께 전환됩니다. 같은 화면에서 색상·이미지·상태·배율을 조절하고 `다음 화면`으로 이동하세요. 공통 리소스는 영향 범위를 안내하며, `전체 구성·리소스`도 유지합니다.

`잠금화면 디자인`에서 비밀번호 표시 1~4번의 입력 전·후 이미지 8개, iOS 키패드 눌림 이미지, 양 플랫폼 숫자·안내·배경색과 Android 누름·패턴 연결선 색을 편집할 수 있습니다.

`전체 구성·리소스`는 26.9.0 기준 iOS 속성 105개, Android 색상 49개, 이미지 82개 그룹/146개 배율·화면별 출력을 다룹니다. 모든 이미지를 상태별·배율별로 교체하고 투명도·인셋·늘림을 조정할 수 있습니다. 리소스 템플릿 ZIP을 내려받아 같은 이름으로 편집 후 일괄 등록할 수 있습니다.

실행취소/다시실행(⌘Z/⇧⌘Z), 디자인을 유지한 새 테마 복제, 배경 이미지 사용 여부·크롭 초점 조절도 추가했습니다. 기존 프로젝트와 키는 그대로 사용합니다.

공통 색상·이미지·말풍선 정책으로 iOS `.ktheme`와 자체 서명한 Android `.apk`를 생성하는 로컬 도구입니다. Mac에서 실행합니다. 원본 이미지와 서명키는 외부 서버로 전송하지 않습니다.

## 실행

Finder에서 **`Studio.command`를 더블클릭**하세요. 터미널과 브라우저가 열립니다. 서버를 종료하려면 해당 터미널에서 Control+C를 누릅니다. 다시 실행하면 기존 실행 창을 찾아 엽니다.

터미널에서 실행하려면 프로젝트 디렉터리에서:

```sh
node scripts/launch.mjs
```

Node.js 22 이상이 필요합니다. 이 컴퓨터에서는 Codex 번들 Node도 런처가 자동으로 찾습니다. 브라우저는 런처가 여는 인증 링크로 접속하세요. 주소의 인증값은 공개 공유하지 마세요.

## 사용 방법

1. 기본 프로젝트에서 시작하거나 `＋`로 새 프로젝트를 만듭니다. 생성 창에서 테마 이름과 공통 패키지명(예: `com.bright.theme.forest`)을 지정할 수 있습니다. 패키지명을 비우면 고유한 값을 자동 생성합니다.
2. 친구·채팅 목록·채팅방·잠금화면·배너·버튼·아이콘·시작화면 중 작업할 화면을 선택합니다.
3. 오른쪽 공통 디자인에서 한 번 등록해 양쪽에 적용합니다. 필요한 항목만 플랫폼별 세부 조정에서 재정의합니다. 공통값은 연결된 화면에 함께 반영되고, 이미지별 재정의가 우선합니다. 설정은 자동 저장됩니다.
4. 같은 화면의 iOS/Android 미리보기와 이미지 출력 대상을 확인하고 `다음 화면`으로 이동합니다. 긴 메시지·선택 상태·Android 잠금 패턴도 전환할 수 있습니다. 공통 팔레트는 `색상과 분위기`에서 조절합니다.
5. `제작자 서명키 관리`에서 키 이름과 **기억할 수 있는 8자 이상 비밀번호**를 정해 자체 키를 생성합니다. 카카오의 키나 유료 인증서는 필요하지 않습니다.
6. `두 플랫폼 생성`을 눌러 `.ktheme`, `.apk`, 전체 결과 ZIP과 보고서를 받습니다.
7. 본인 iPhone/Android에서 실제 카카오톡 적용 결과를 확인합니다. 미리보기는 예상 화면입니다.

서버 재실행 후에는 키 관리에서 기존 키를 선택하고 비밀번호를 입력해 잠금을 해제하세요. 비밀번호는 디스크에 저장하지 않고 서버 프로세스 메모리에만 유지합니다. **키 파일과 비밀번호를 분실하면 기존 테마 업데이트가 어려워집니다.** 키 백업은 비밀번호로 암호화된 `.p12`이며, 백업 키 복원도 지원합니다. 비밀번호를 새로 바꾸는 기능은 아직 없습니다.

프로젝트 백업 ZIP에는 디자인과 이미지가 들어가며 개인키는 들어가지 않습니다. 다른 컴퓨터에서는 프로젝트와 키를 각각 복원하세요. 이미 같은 ID의 프로젝트가 있으면 가져오기로 덮어쓰지 않고 기존 프로젝트를 열도록 안내합니다.

패키지명은 소문자로 시작하는 3개 이상의 구간을 점으로 연결하며, 소문자·숫자·밑줄만 사용할 수 있습니다(최대 160자, Java 예약어 제외). 같은 데이터 저장소의 기존 프로젝트와 중복될 수 없고 생성 후에는 변경할 수 없습니다. 배포한 테마의 업데이트에는 같은 패키지명과 서명키를 사용하세요. iOS 테마 ID와 Android 패키지명은 입력한 값을 동일하게 사용합니다. 기존 프로젝트도 다시 생성하면 iOS의 자동 `.ios` 접미사가 없어집니다. 이전에 배포한 iOS 테마와는 ID가 달라지며, 이미 생성한 파일은 변경되지 않습니다. 이 출력 변경의 compilerVersion은 0.4.1입니다. 기존 프로젝트와 자동 생성되는 기본 프로젝트·테마 복제의 ID 관리 방식은 유지됩니다.

## 현재 구현 범위

- 프로젝트 생성·자동 저장·전환·ZIP 백업/가져오기.
- 공통 10색 팔레트, 세 가지 시작 팔레트, 제작자·버전·라이트/다크 모드.
- 공통 배경·말풍선·프로필·테마 아이콘·8개 탭 및 세부 상태·배율별 이미지 등록.
- 모서리·여백에 맞춘 색상 본체와 선택적 캐릭터 합성 말풍선, 첫/연속 독립 설정, iOS 인셋과 Android 9-patch 출력. 이미지 본체 원본은 64×56 기준입니다.
- 생성 이미지로 표시하는 두 플랫폼 6개 예상 화면, PNG 캡처.
- 자체 release 키 생성·잠금 해제·암호화 키 백업/복원, fingerprint 일치 검사.
- iOS ZIP 패키징, 실제 Android 리소스·DEX 컴파일, 정렬·서명·검증, versionCode 자동 증가.
- 작업 큐, 진행 상태, Android 실패 시 성공한 iOS 파일 별도 다운로드, 결과 이력.
- 로컬 인증, Origin/Host 검사, 자산 경로·이미지·ZIP 크기 검증.

## 검증 상태와 한계

**실제 빌드와 서명, Android 13 에뮬레이터 설치·실행·같은 키의 업데이트 설치를 확인했습니다.** 자동 테스트와 브라우저 검증도 수행했습니다. 상세 근거는 `docs/VERIFICATION.md`에 있습니다.

**카카오톡 내부의 테마 적용, 실제 iPhone 적용은 아직 검증하지 못했습니다.** 호환성 프로필은 조사한 26.9.0을 기반으로 한 것이며 모든 버전의 실제 동작을 보장하지 않습니다. 생성 보고서도 `deviceVerified: false`를 유지합니다.

미리보기는 자체 Canvas 화면입니다. 실제 카카오톡의 레이아웃·글꼴·줄바꿈과 차이가 있고, 카카오톡 레이아웃 자체를 바꾸지는 않습니다. 이미지 본체 원본은 64×56 기준으로 변환하고 색상 본체는 모서리·여백에 맞춰 생성합니다. 캐릭터의 위쪽 공간은 본체 높이와 분리하며, 고정 크기 캐릭터를 담을 최소 가로 공간은 필요합니다. 개별 가이드가 있는 출력은 장식과 겹치지 않는지 확인하세요. 선택 상태는 iOS의 선택 이미지와 글자색을 사용하고 Android는 실제 지원되는 누름 색상 등의 상태를 표시합니다. 휴대폰 세로 기본 프로필 외 태블릿·가로·지역별 탭의 정밀 검증은 후속 작업입니다.

작업 취소, Keychain 연동, 일괄 변형 생성, SVG 업로드는 아직 구현하지 않았습니다. 현재 편집기는 빌드 단계가 필요 없는 JavaScript 모듈로 작성했습니다. 상세 범위는 지원 항목표를 기준으로 확인하세요.

## Android 빌드 환경

JDK 17 이상, Android SDK Build Tools 37 이상과 안정 버전 Android SDK Platform 37 이상이 필요합니다. 현재 Android 17 기준으로 **targetSdk 37 / minSdk 28(Android 9)**을 사용합니다. 이 컴퓨터에 공식 `platforms;android-37.2`와 `build-tools;37.0.0`을 추가 설치해 실제 APK 컴파일·서명·정렬·같은 키 업데이트를 검증했습니다. 오래된 SDK만 있으면 구버전 대상으로 생성하지 않고 설치할 패키지를 안내합니다. 이 변경 후 Android 17 기기 설치·카카오톡 적용은 별도 확인 대상입니다.

```sh
node src/cli.mjs doctor
sdkmanager "platforms;android-37.2" "build-tools;37.0.0"
```

자동 탐색되지 않으면 `JAVA_HOME`, `ANDROID_SDK_ROOT`를 지정하세요. 전역 도구를 변경하지 않고 Android 공식 AAPT2, javac, D8, zipalign, apksigner를 직접 실행합니다. Gradle·Android Studio를 매번 실행할 필요는 없습니다.

## 다른 환경에서 설치

이 전달본에는 실행 의존성이 포함되어 있습니다. 소스만 복사한 경우 Node를 설치한 뒤:

```sh
npm install
npx playwright install chromium
```

의존성 버전을 고정한 `pnpm-lock.yaml`도 포함되어 있습니다. 재현 가능한 설치는 `pnpm install --frozen-lockfile`을 사용하세요. Playwright/Chromium은 브라우저 테스트용이며 일반 실행에는 필요하지 않습니다.

## 개발·후속 agent

먼저 `AGENTS.md`, `docs/HANDOFF.md`, `docs/ARCHITECTURE.md`를 읽으세요. 테스트 명령은 `docs/TESTING.md`에 있습니다. 글로벌 스킬 설치는 필요하지 않습니다.

`examples/sample-project.zip`에는 새 샘플 프로젝트 한 개가 들어 있습니다. 연결된 서명키는 없으며 APK를 만들 때 제작자 키를 새로 생성하면 됩니다.

본 도구는 카카오의 공식 제품이 아닙니다. 기본 이미지는 코드로 만든 중립 도형이며 공식 캐릭터 이미지를 포함하지 않습니다. 참조 규격 출처는 `templates/NOTICE.md`에 기록했습니다.
